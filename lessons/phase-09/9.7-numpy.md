## 📖 開場故事：一次處理一整排的計算機

你是超市的店長，要把 1,000 樣商品**全部打 9 折**。

**用一般計算機**：一樣一樣按，「100 × 0.9 =」、「250 × 0.9 =」……按 1,000 次。

**用試算表**：在一欄輸入公式 `=A1*0.9`，往下一拉，1,000 樣**一次全部算完**。

> 🧮 **NumPy 就是 Python 的「整排計算機」**：9.6 的串列要用迴圈一個一個算；NumPy 陣列可以直接寫 `prices * 0.9`，一次算完整排，而且速度快很多。下一單元的 pandas，就是建立在 NumPy 之上的。

## 🧠 正文

### 1. 建立陣列

```python
import numpy as np

prices = np.array([100, 102, 101, 105, 103, 108, 107, 110])
print(prices)
print(prices * 1.1)          # 整排乘以 1.1，不用迴圈
print(prices.max(), prices.min(), prices.mean())
```

輸出：

```
[100 102 101 105 103 108 107 110]
[110.  112.2 111.1 115.5 113.3 118.8 117.7 121. ]
110 100 104.5
```

> 💡 `import numpy as np` 是慣例寫法：匯入 NumPy，並取個簡短的別名 `np`。全世界的人都這樣寫，你在網路上看到的範例也是。

| | 串列（list） | NumPy 陣列（array） |
|---|---|---|
| 數學運算 | `[1,2] * 2` → `[1, 2, 1, 2]`（重複！） | `np.array([1,2]) * 2` → `[2 4]` |
| 速度 | 慢（大量資料時） | 快 |
| 內容 | 可以混合各種型別 | 通常是同一種型別（數字） |

### 2. ⭐ 向量化計算報酬率

9.4 用迴圈、9.6 用串列生成式算每日報酬；NumPy 用**切片錯位相除**一行完成：

```python
rets = prices[1:] / prices[:-1] - 1
print(rets.round(4))
```

輸出：

```
[ 0.02   -0.0098  0.0396 -0.019   0.0485 -0.0093  0.028 ]
```

| 部分 | 內容 | 意思 |
|---|---|---|
| `prices[1:]` | 102, 101, 105, …, 110 | 「今天」的價格（從第 2 天開始） |
| `prices[:-1]` | 100, 102, 101, …, 107 | 「昨天」的價格（到倒數第 2 天） |
| 相除 − 1 | | 每一天的報酬 |

> 🔑 **向量化（vectorization）** = 用整排運算取代迴圈。這是 NumPy 和 pandas 的核心精神，Phase 10 的「向量化回測」就是這個概念。

### 3. ⭐ 平均、標準差、累積報酬

```python
print(f"平均日報酬：{rets.mean():.4%}")
print(f"日報酬標準差：{rets.std(ddof=1):.4%}")

total_ret = (1 + rets).prod() - 1        # 把每天的 (1 + 報酬) 連乘
print(f"累積報酬：{total_ret:.2%}")
print(f"驗算：{prices[-1] / prices[0] - 1:.2%}")

growth = (1 + rets).cumprod()            # 每一天的累積成長倍數
print(growth.round(4))
```

輸出：

```
平均日報酬：1.4011%
日報酬標準差：2.6713%
累積報酬：10.00%
驗算：10.00%
[1.02 1.01 1.05 1.03 1.08 1.07 1.1 ]
```

| 函式 | 意思 | 回想 |
|---|---|---|
| `.mean()` | 平均 | 3.6 |
| `.std(ddof=1)` | 樣本標準差（`ddof=1` 表示除以 n−1，和試算表的 STDEV 相同） | 3.6 |
| `.prod()` | 全部連乘 | 3.1 複利 |
| `.cumprod()` | 累積連乘（每一步的結果都留下來） | 資金曲線 |

> ⚠️ **累積報酬要用連乘，不是把每天的報酬加起來**（回想 3.1、3.2）。把日報酬相加，在波動大或期間長時會有明顯誤差。

### 4. ⭐ 年化報酬與年化波動

一年大約有 **252 個交易日**（各市場、各年度略有不同，這是常用的近似值）。

| 指標 | 公式（近似） |
|---|---|
| **年化報酬**（幾何） | （1 + 總報酬）^（252 ÷ 天數）− 1 |
| **年化波動** | 日報酬標準差 × √252 |

```python
daily_std = 0.012
print(f"年化波動 ≈ {daily_std * np.sqrt(252):.2%}")
```

輸出：`年化波動 ≈ 19.05%`

> 💡 **為什麼是 √252 而不是 × 252？** 波動度不像報酬那樣直接相加。如果每天的漲跌彼此獨立，**變異數**（標準差的平方）會隨天數相加，所以標準差隨「天數的平方根」放大。生活比喻：喝醉的人隨機走路，走 100 步並不會離起點 100 步遠，平均大約只遠了 √100 = 10 步左右——因為很多步互相抵消了。

### 5. ⭐ 一行算出最大回撤

```python
equity = np.array([100, 110, 105, 120, 96, 100, 130])
peak = np.maximum.accumulate(equity)   # 到目前為止的最高點
drawdown = equity / peak - 1

print(peak)
print(drawdown.round(3))
print(f"最大回撤：{drawdown.min():.1%}")
```

輸出：

```
[100 110 110 120 120 120 130]
[ 0.     0.    -0.045  0.    -0.2   -0.167  0.   ]
最大回撤：-20.0%
```

> 🔑 和 9.4 的迴圈版、9.5 的函式版結果一樣（−20%），但**不需要寫迴圈**。`np.maximum.accumulate` 就是「一路記住最高點」。

### 6. 布林遮罩與 np.where

```python
up = rets > 0
print(up)
print(f"上漲天數：{up.sum()}，上漲比例：{up.mean():.1%}")
print(rets[up].round(4))                  # 只取出上漲的日子
print(np.where(rets > 0, "漲", "跌"))     # 條件成立取前者，否則取後者
```

輸出：

```
[ True False  True False  True False  True]
上漲天數：4，上漲比例：57.1%
[0.02   0.0396 0.0485 0.028 ]
['漲' '跌' '漲' '跌' '漲' '跌' '漲']
```

| 技巧 | 意思 |
|---|---|
| `rets > 0` | 產生一排 True / False（**布林遮罩**） |
| `.sum()` | True 當作 1、False 當作 0 → 計數 |
| `.mean()` | True 的比例 |
| `rets[up]` | 只取出遮罩為 True 的元素 |
| `np.where(條件, A, B)` | 向量化的 if / else |

### 7. ⭐ 蒙地卡羅模擬：一萬組 20 筆交易

回想 3.12、7.5：勝率 40%、賺 2R 賠 1R 的策略，一組 20 筆交易**虧錢的機率**有多高？

```python
rng = np.random.default_rng(42)             # 固定亂數種子，結果可以重現

wins = rng.random((10000, 20)) < 0.4        # 1 萬組 × 20 筆，每筆有 40% 機率獲利
r = np.where(wins, 2.0, -1.0)               # 贏 +2R、輸 −1R
total_r = r.sum(axis=1)                     # 每一組（每一列）的總 R

print(f"每組平均總 R：{total_r.mean():.2f}")
print(f"虧錢的組別比例：{(total_r < 0).mean():.1%}")
```

輸出：

```
每組平均總 R：3.98
虧錢的組別比例：25.1%
```

> 🔑 理論期望值：每筆 0.4 × 2 − 0.6 × 1 = 0.2R，20 筆 = 4R，模擬結果 3.98 非常接近 ✅（理論上虧錢的機率約 25.0%）。而**約四分之一的組別是虧錢的**——和 7.5「好策略也約每 4 組有 1 組虧錢」一致。在 Phase 3 你用試算表做這件事，現在 4 行程式、不到一秒就完成了。

| 部分 | 意思 |
|---|---|
| `rng.random((10000, 20))` | 產生 1 萬 × 20 的表格，每格是 0～1 的亂數 |
| `axis=1` | 沿著「每一列」加總（每一組 20 筆） |
| 亂數種子 `42` | 固定種子 → 每次執行結果相同，方便別人重現 |

## 📌 重點整理

1. NumPy 陣列 = **整排計算機**：`prices * 1.1` 一次算完，不用迴圈（**向量化**）。
2. 每日報酬：`prices[1:] / prices[:-1] - 1`。
3. `.mean()`、`.std(ddof=1)`、`.prod()`、`.cumprod()`；**累積報酬用連乘**。
4. 年化：報酬用幾何年化；**波動 × √252**（變異數隨時間相加）。
5. 最大回撤：`equity / np.maximum.accumulate(equity) - 1` 的最小值。
6. **布林遮罩**篩選、`np.where` 做向量化的 if / else。
7. 亂數加固定種子，做可重現的**蒙地卡羅模擬**。

## ❌ 常見誤解

| 誤解 | 事實 |
|---|---|
| 「累積報酬 = 每日報酬加總」 | 要用連乘 (1+r) 再減 1；相加只是近似，期間長、波動大時誤差明顯。 |
| 「年化波動 = 日波動 × 252」 | 波動度要乘以 √252，因為變異數（而非標準差）隨時間相加。 |
| 「串列和陣列用起來一樣」 | 串列 × 2 是重複清單；陣列 × 2 是每個元素乘以 2。 |
| 「亂數模擬每次結果都不同，所以不可靠」 | 固定亂數種子就能重現；模擬次數夠多時結果會很穩定。 |

## ✅ 自我測驗

**Q1. `prices[1:] / prices[:-1] - 1` 為什麼能算出每日報酬？**

<details><summary>看答案</summary>

`prices[1:]` 是從第 2 天到最後一天的價格（今天），`prices[:-1]` 是從第 1 天到倒數第 2 天的價格（昨天），兩者長度相同且錯開一天，對應位置相除就是「今天 ÷ 昨天」，減 1 即為每日報酬。

</details>

**Q2. 為什麼年化波動要乘以 √252？**

<details><summary>看答案</summary>

假設每日報酬彼此獨立，變異數會隨天數相加：一年的變異數 ≈ 252 × 日變異數。標準差是變異數的平方根，所以年化標準差 ≈ √252 × 日標準差。直覺上，很多天的漲跌會互相抵消，所以波動不會隨天數等比例放大。

</details>

**Q3. 練習 2 參考答案（理論值）**

<details><summary>看答案</summary>

期望值：策略 1 = 0.4×2 − 0.6×1 = 0.2R/筆（20 筆 4R）；策略 2 = 0.6×1 − 0.4×1 = 0.2R/筆（20 筆 4R）；策略 3 = 0.3×3 − 0.7×1 = 0.2R/筆（20 筆 4R）。三者期望值相同！但「20 筆一組虧錢」的機率不同（二項分布理論值）：策略 1 約 **25%**（贏 ≤ 6 筆）、策略 2 約 **13%**（贏 ≤ 9 筆；另有約 12% 剛好打平）、策略 3 約 **24%**（贏 ≤ 4 筆；另有約 18% 剛好打平）。高勝率的策略 2 最少出現虧損組別；低勝率的策略 1、3 雖然期望值一樣，卻更常碰到虧錢的組別和更長的連虧——這就是 3.5 說的：勝率和賠率會改變「過程的感受」，不只改變結果。你的模擬數字應該很接近這些理論值。

</details>
