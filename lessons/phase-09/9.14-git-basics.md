## 📖 開場故事：遊戲存檔

玩角色扮演遊戲時，你一定會在打大魔王之前**存檔**：

- 打贏了 → 繼續前進，再存一次檔
- 打輸了 → **讀取存檔**，回到打魔王之前，換個策略再試一次
- 想嘗試另一條劇情線 → 另開一個存檔欄位，兩條路線互不影響

如果遊戲沒有存檔功能，你每次輸了都要從頭玩起——沒有人受得了。

> 💾 **Git 就是程式的存檔系統**：每次改好一個段落就存一次檔（commit），寫壞了可以讀回之前的版本，還能記錄「每一次改了什麼、為什麼改」。對回測研究特別重要：**三個月後你會想知道「當初那個漂亮的回測結果，到底是用哪一版程式、哪些參數跑出來的？」**

## 🧠 正文

### 1. 為什麼回測研究需要版本控制？

| 沒有版本控制 | 有版本控制 |
|---|---|
| 檔名變成 `策略_v2_最終版_真的最終版_改3.ipynb` | 一個檔案，所有版本都記錄在 Git 裡 |
| 改壞了回不去 | 隨時讀回任何一個存檔點 |
| 不知道結果是哪一版跑出來的 | 每一次 commit 都有時間、說明、完整內容 |
| 偷偷改參數讓回測變漂亮，沒人知道（包括你自己） | 每一次修改都留下紀錄（呼應 8.13 的版本管理） |

> 🔑 回想 4.12、8.13：**過度擬合常常發生在「不知不覺改了很多次參數」**。Git 的紀錄會誠實告訴你：你為了讓回測變漂亮，總共改了幾次。

### 2. ⭐ 三個區域

| 區域 | 意思 | 遊戲比喻 |
|---|---|---|
| **工作區** | 你正在編輯的檔案 | 正在玩的遊戲畫面 |
| **暫存區（staging）** | 準備要存檔的變更 | 選好要存進存檔的進度 |
| **儲存庫（repository）** | 所有存檔點的紀錄 | 存檔欄位 |

**流程：** 修改檔案 → `git add`（放進暫存區）→ `git commit`（存檔）

### 3. 安裝與設定

- **Windows / Mac**：到 Git 官方網站下載安裝（Mac 也可能已內建）
- **Colab**：已經內建 Git（但 Colab 環境會重置，見第 8 節）
- **VS Code**：內建 Git 圖形介面，安裝 Git 後就能用按鈕操作

第一次使用時，設定你的名字和 email（會記錄在每一次存檔中）：

```bash
git config --global user.name "你的名字"
git config --global user.email "you@example.com"
```

### 4. ⭐ 最常用的 6 個指令

**① 建立儲存庫**

```bash
mkdir trading-research
cd trading-research
git init
```

**② 查看狀態**（最常用！不知道現在狀況時就打這個）

```bash
git status
```

**③ 加入暫存區**

```bash
git add indicators.py            # 加入單一檔案
git add .                        # 加入所有變更（小心：先確認 .gitignore，見第 6 節）
```

**④ 存檔（提交）**

```bash
git commit -m "新增 RSI 與 ATR 指標函式"
```

**⑤ 查看歷史**

```bash
git log --oneline
```

輸出範例：

```
a3f9c21 修正 RSI 的平滑法為 Wilder
7b2e810 新增 RSI 與 ATR 指標函式
1c4d5e9 初始化專案
```

**⑥ 查看改了什麼**

```bash
git diff                         # 尚未加入暫存區的變更
git diff 7b2e810 a3f9c21         # 兩個存檔點之間的差異
```

| 指令 | 意思 | 遊戲比喻 |
|---|---|---|
| `git init` | 建立儲存庫 | 開新遊戲 |
| `git status` | 目前狀態 | 看看現在在哪 |
| `git add` | 選擇要存檔的變更 | 選擇存檔內容 |
| `git commit -m "說明"` | 存檔，並寫下說明 | 存檔並命名 |
| `git log` | 查看存檔紀錄 | 看存檔列表 |
| `git diff` | 比較差異 | 比較兩個存檔的不同 |

### 5. ⭐ 寫好的存檔說明

| ❌ 不好的說明 | ✅ 好的說明 |
|---|---|
| 「更新」 | 「RSI 改用 Wilder 平滑法，和 TradingView 一致」 |
| 「改參數」 | 「均值回歸策略停損從 2ATR 改為 3ATR（v1.1，見規格書）」 |
| 「fix」 | 「修正突破訊號：20 日最高價加上 shift(1)，避免包含今天」 |

> 🔑 **說明要寫「為什麼」**，不只是「做了什麼」。三個月後的你會感謝現在的你。

### 6. ⭐ .gitignore：不該放進 Git 的東西

在專案資料夾建立一個名為 `.gitignore` 的文字檔，列出 Git 要忽略的檔案：

```text
# 資料檔（太大、可以重新下載）
data/*.csv

# 密碼與金鑰（絕對不能上傳！）
.env
secrets.py

# 系統與暫存檔
.ipynb_checkpoints/
__pycache__/
.DS_Store
```

| 不該放進 Git 的 | 理由 |
|---|---|
| **API 金鑰、密碼、券商帳號** | 🚨 上傳到 GitHub 公開專案，幾分鐘內就可能被自動掃描盜用；就算之後刪除，歷史紀錄裡還是看得到 |
| 大型資料檔 | Git 不適合存大檔案；資料可以重新下載（但要記錄來源與下載日期，9.10） |
| 暫存檔、系統檔 | 沒有用、只會干擾 |

> ⚠️ **金鑰的正確做法**：存在不會被上傳的檔案（例如 `.env`）或環境變數中，程式執行時再讀取。如果不小心上傳了，**立刻到該服務撤銷並重新產生金鑰**——刪除檔案是不夠的。

### 7. 回到之前的版本

```bash
git restore indicators.py              # 放棄這個檔案「還沒存檔」的修改，回到上次存檔的樣子
git log --oneline                      # 找到想看的存檔點代號
git show 7b2e810:indicators.py         # 看某個存檔點時，這個檔案長什麼樣子
git checkout 7b2e810 -- indicators.py  # 把這個檔案恢復成那個存檔點的版本
```

> ⚠️ `git restore` 會**丟掉**還沒存檔的修改，執行前確認你真的不要它了。新手原則：**勤存檔**——每完成一個小段落就 commit 一次，就不太需要擔心改壞。

### 8. GitHub 與 Colab

**GitHub** = 放在網路上的存檔櫃：備份你的儲存庫、在不同電腦之間同步、和別人分享或合作。

| 操作 | 指令 |
|---|---|
| 把本機儲存庫連到 GitHub | `git remote add origin <GitHub 給你的網址>` |
| 上傳 | `git push -u origin main` |
| 下載別人的專案 | `git clone <網址>` |
| 取得最新版本 | `git pull` |

**Colab 使用者：**
- Colab 的環境**會重置**，在裡面打的 git 指令和檔案不會永久保存
- 簡單的做法：選單「檔案 → 在 GitHub 中儲存副本」，把筆記本存到你的 GitHub 儲存庫
- 或把筆記本存在 Google 雲端硬碟（它也有簡單的版本紀錄）

> 💡 **公開還是私人？** 學習筆記可以公開分享；但包含**個人交易紀錄、資金規模、券商資訊**的專案，建議設為**私人（Private）**。

### 9. 建議的專案資料夾結構

```text
trading-research/
├── .gitignore
├── README.md               ← 這個專案在做什麼、怎麼執行
├── data/                   ← 資料檔（被 .gitignore 忽略）
├── indicators.py           ← 9.13 的指標函式庫
├── notebooks/
│   ├── 01_data_check.ipynb
│   └── 02_0050_analysis.ipynb
└── specs/                  ← Phase 8 的策略規格書
    ├── trend_v1.0.md
    └── mean_reversion_v1.0.md
```

> 💾 Phase 10 開始，你會寫越來越多回測程式和報告。**現在就建立好這個習慣**：一個專案資料夾、用 Git 存檔、規格書和程式放在一起。

## 📌 重點整理

1. Git = **程式的存檔系統**：隨時讀回舊版本、記錄每次改了什麼與為什麼。
2. 回測研究特別需要：**可重現**、**防止不自覺的過度擬合**。
3. 流程：修改 → `git add` → `git commit -m "說明"`；不確定時 `git status`。
4. 存檔說明要寫**為什麼**。
5. `.gitignore`：**金鑰與密碼絕對不能上傳**；大型資料檔也不要放。
6. GitHub = 網路上的存檔櫃；Colab 用「在 GitHub 中儲存副本」。
7. 勤存檔：每完成一個小段落就 commit。

## ❌ 常見誤解

| 誤解 | 事實 |
|---|---|
| 「Git 就是 GitHub」 | Git 是在你電腦上的版本控制工具；GitHub 是存放 Git 儲存庫的網路服務。 |
| 「存檔太多次很浪費」 | 勤存檔讓你更容易回到正確的版本；每個 commit 都很小。 |
| 「上傳金鑰後刪掉檔案就安全了」 | Git 歷史紀錄中仍然看得到；必須到該服務撤銷並重新產生金鑰。 |
| 「只有工程師才需要版本控制」 | 任何需要重現結果、追蹤修改的研究工作都需要，包括回測。 |

## 🛠️ 練習（約 45 分鐘）

**練習 1：建立你的研究儲存庫**
在自己的電腦上（或 VS Code 中）建立 `trading-research` 資料夾，依第 9 節的結構建立資料夾與 `.gitignore`，把 9.13 的 `indicators.py` 放進去，完成第一次 commit。

**練習 2：修改與比較**
修改 `indicators.py`（例如把 RSI 的預設期數改成 10），用 `git diff` 看看差異，再用 `git restore` 放棄這個修改。然後做一個「有意義的修改」（例如新增 9.13 練習 3 的 `donchian` 函式），寫一個好的說明並 commit。用 `git log --oneline` 查看紀錄。

**練習 3：上傳到 GitHub（選做）**
註冊 GitHub 帳號，建立一個**私人**儲存庫，把練習 1 的專案 push 上去。

## ✅ 自我測驗

**Q1. 為什麼回測研究特別需要版本控制？**

<details><summary>看答案</summary>

1. 可重現：能確認某個回測結果是用哪一版程式、哪些參數跑出來的；2. 能回到之前正確的版本；3. 誠實記錄每一次修改，避免不自覺地反覆調整參數造成過度擬合；4. 配合策略規格書的版本管理（8.13）。

</details>

**Q2. 哪些檔案不應該放進 Git？為什麼？**

<details><summary>看答案</summary>

API 金鑰、密碼、帳號等機密資訊（上傳後可能被盜用，且刪除檔案後歷史紀錄中仍看得到）；大型資料檔（Git 不適合，且可以重新下載，只要記錄來源）；系統與暫存檔（沒有用處）。用 .gitignore 列出要忽略的檔案。

</details>

**Q3. `git add` 和 `git commit` 有什麼不同？**

<details><summary>看答案</summary>

`git add` 把變更放進暫存區，選擇「哪些修改要存進這次存檔」；`git commit` 才真正建立一個存檔點，並附上說明。可以先 add 多個檔案，再一次 commit。

</details>
