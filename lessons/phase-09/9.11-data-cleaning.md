## 📖 開場故事：洗菜、挑掉爛葉

從市場買回一把青菜，你不會直接下鍋：

1. **洗掉泥沙**（明顯的錯誤資料）
2. **挑掉爛葉**（異常值）
3. **檢查份量**：老闆是不是少給了？（缺值）
4. **切成一樣的大小**，才會熟得均勻（統一格式）

但也要小心不要**洗過頭**：把好好的葉子也丟掉，最後剩沒幾根（刪掉太多資料）。

> 🥬 **資料清理就是洗菜**：拿到資料後，修正錯誤、處理缺漏、統一格式。其中最重要、也最容易被忽略的一步是**除權息調整**——就像菜的重量包含了泥土，你以為買了 1 斤，洗完只剩 8 兩。不調整的話，回測會以為「每年除息那天都大跌」，嚴重低估真實報酬。

## 🧠 正文

### 1. 常見的髒資料

| 問題 | 例子 | 檢查方法（9.10） |
|---|---|---|
| **缺值** | 某天的收盤價是空的（NaN） | `df.isna().sum()` |
| **重複** | 同一天出現兩筆 | `df.index.duplicated().sum()` |
| **順序錯亂** | 日期沒有由舊到新排列 | `df.index.is_monotonic_increasing` |
| **異常值** | 價格多打一個 0、成交量為 0 | 單日漲跌幅、價格合理性 |
| **除權息 / 分割** | 價格在某天突然大跌，但其實沒有虧錢 | 單日跌幅超過漲跌幅限制 |

### 2. ⭐ 重複與順序

```python
import pandas as pd
import numpy as np

dirty = pd.DataFrame(
    {"Close": [101.0, 102.5, 102.5, 100.8, np.nan, 103.2]},
    index=pd.to_datetime(["2024-01-03", "2024-01-02", "2024-01-03",
                          "2024-01-04", "2024-01-05", "2024-01-08"]),
)
print(dirty)

clean = dirty[~dirty.index.duplicated(keep="first")]   # 移除重複的日期（保留第一筆）
clean = clean.sort_index()                             # 依日期排序
print(clean)
```

輸出：

```
            Close
2024-01-03  101.0
2024-01-02  102.5
2024-01-03  102.5
2024-01-04  100.8
2024-01-05    NaN
2024-01-08  103.2
            Close
2024-01-02  102.5
2024-01-03  101.0
2024-01-04  100.8
2024-01-05    NaN
2024-01-08  103.2
```

> 💡 `~` 是「反過來」的意思：`duplicated()` 標出重複的列，`~` 之後就變成「不重複的列」。
>
> ⚠️ 重複的兩筆數字不一樣時（例如 101.0 和 102.5），要保留哪一筆？**沒有標準答案**，要回頭查資料來源，或用另一個來源比對。重點是：**發現了、處理了、記錄下來**。

### 3. ⭐ 缺值：dropna、ffill，以及禁止 bfill

| 方法 | 做法 | 適合 | 風險 |
|---|---|---|---|
| `dropna()` | 刪掉有缺值的列 | 缺值很少、刪掉不影響 | 刪太多會讓資料不連續 |
| `ffill()` | 用**前一天**的值填補 | 停牌、假日：價格沒變就是沿用昨天 | 長時間停牌會造成假的「價格不動」 |
| `bfill()` | 用**後一天**的值填補 | ❌ **回測中不要用** | **用到未來的資料（前視偏差）** |
| `interpolate()` | 用前後的值內插 | ❌ 回測中也要避免 | 同樣用到了未來的值 |

```python
print(clean["Close"].ffill())
```

> 🔑 **為什麼不能 bfill？** 1 月 5 日的資料缺了，如果用 1 月 8 日的價格填進去，等於 1 月 5 日「提前知道」了 1 月 8 日的價格。在回測中，這就是偷看答案。**填補缺值時，只能用過去的資訊**——和 9.8 的 `shift(-1)` 是同一個道理。

### 4. 合併不同市場：交易日不一致

台股和美股的假日不同，合併在一起時會出現缺值：

```python
tw = pd.Series([100.0, 101.0, 102.0],
               index=pd.to_datetime(["2024-07-03", "2024-07-04", "2024-07-05"]), name="TW")
us = pd.Series([500.0, 505.0],
               index=pd.to_datetime(["2024-07-03", "2024-07-05"]), name="US")  # 7/4 美國國慶休市

both = pd.concat([tw, us], axis=1)
print(both)
print(both.ffill())
```

輸出：

```
               TW     US
2024-07-03  100.0  500.0
2024-07-04  101.0    NaN
2024-07-05  102.0  505.0
               TW     US
2024-07-03  100.0  500.0
2024-07-04  101.0  500.0
2024-07-05  102.0  505.0
```

> 💡 美股 7/4 休市，用前一天的價格填補（ffill）代表「這天美股價格沒變，報酬為 0」，這是合理的處理。
>
> ⚠️ 還要注意**時差**：台股收盤時，美股還沒開盤。如果策略用「美股昨晚的漲跌」來決定台股今天的交易，日期要小心對齊，避免用到還沒發生的資料。

### 5. ⭐⭐ 除權息調整

**問題在哪裡？**

假設某 ETF 收盤 102 元，隔天除息，每股配發 **2 元**現金股利。除息日的開盤參考價會變成 102 − 2 = 100 元。

- 如果你**持有**這檔 ETF：股價少了 2 元，但你拿到 2 元現金 → **其實沒有虧錢**
- 但**原始價格**看起來像是「跌了 2%」

如果用原始價格回測，每年除息那天都會被當成虧損，**長期報酬被嚴重低估**；而且像 8.4 的突破、8.5 的均值回歸這類規則，也可能被這個「假跌幅」觸發假訊號。

```python
d = pd.DataFrame(
    {"Close":    [100, 101, 102, 100, 101, 103],
     "Dividend": [0,   0,   0,   2,   0,   0]},      # 第 4 天除息，每股 2 元
    index=pd.bdate_range("2024-07-01", periods=6),
)
d["RawRet"] = d["Close"].pct_change()                              # 原始價格的報酬
d["TotalRet"] = (d["Close"] + d["Dividend"]) / d["Close"].shift(1) - 1   # 含股利的真實報酬

# 計算還原價格：除息日「之前」的價格，都乘上 (1 − 股利 ÷ 前一天收盤)
factor = (1 - d["Dividend"] / d["Close"].shift(1)).fillna(1)
cum_factor = factor[::-1].cumprod()[::-1].shift(-1).fillna(1)
d["AdjClose"] = d["Close"] * cum_factor
d["AdjRet"] = d["AdjClose"].pct_change()

print(d.round(4))
```

輸出：

```
            Close  Dividend  RawRet  TotalRet  AdjClose  AdjRet
2024-07-01    100         0     NaN       NaN   98.0392     NaN
2024-07-02    101         0  0.0100    0.0100   99.0196  0.0100
2024-07-03    102         0  0.0099    0.0099  100.0000  0.0099
2024-07-04    100         2 -0.0196    0.0000  100.0000  0.0000
2024-07-05    101         0  0.0100    0.0100  101.0000  0.0100
2024-07-08    103         0  0.0198    0.0198  103.0000  0.0198
```

| 欄位 | 除息日（7/4）的報酬 | 意思 |
|---|---|---|
| RawRet（原始） | **−1.96%** | 看起來跌了，其實是配息 |
| TotalRet（含股利） | **0%** | 真實的投資報酬 |
| AdjRet（還原價格） | **0%** | 和真實報酬一致 ✅ |

```python
print(f"原始價格的期間報酬：{d['Close'].iloc[-1] / d['Close'].iloc[0] - 1:.2%}")
print(f"還原價格的期間報酬：{d['AdjClose'].iloc[-1] / d['AdjClose'].iloc[0] - 1:.2%}")
```

輸出：

```
原始價格的期間報酬：3.00%
還原價格的期間報酬：5.06%
```

> 🔑 **還原價格的做法**：把除息日**之前**的所有價格往下調整，讓除息日的價格變化只反映真實的漲跌。所以還原價格的「過去」會比原始價格低（7/1 的 100 元變成 98.04 元），**最新的價格則和原始價格相同**。
>
> 💡 程式中 `factor[::-1].cumprod()[::-1].shift(-1)` 的意思是：從最新的一天往回累乘調整比例，再往前移一天（因為除息日當天的價格不用調整，要調整的是它「之前」的價格）。看不懂沒關係，**重點是理解為什麼要調整**；實務上 yfinance 的 `Adj Close` 或 `auto_adjust=True` 已經幫你算好了。

> ⚠️ **差距會隨時間累積**：每年配息 3%～4% 的 ETF，10 年下來原始價格和還原價格的報酬可能差距很大。以高股息 ETF 為例，只看原始價格甚至可能誤以為「十年都沒漲」。

### 6. ⭐ 股票分割調整

**股票分割**：例如「1 拆 4」，每 1 股變成 4 股，股價變成約四分之一，**總市值不變**。

```python
s = pd.Series([400, 404, 396, 100, 101, 99.5],
              index=pd.bdate_range("2024-06-10", periods=6))   # 第 4 天 1 拆 4
print(s.pct_change().round(4))

adj = s.copy()
adj.iloc[:3] = adj.iloc[:3] / 4      # 分割前的價格除以 4
print(adj.pct_change().round(4))
```

| 日期 | 原始價格 | 原始報酬 | 調整後價格 | 調整後報酬 |
|---|---:|---:|---:|---:|
| 6/12 | 396 | −1.98% | 99.0 | −1.98% |
| 6/13（分割） | 100 | **−74.75%** | 100.0 | **+1.01%** |

> 🚨 **不調整的話，回測會以為這天暴跌 75%**，所有停損都會被觸發、最大回撤變成 −75%。
>
> 💡 美股的分割很常見；台股過去較少見，但近年也有案例（例如 0050 在 2025 年進行了 1 拆 4 的分割，以官方公告為準）。**如果你下載 0050 的原始價格做課綱作業，一定會碰到這個問題**——這也是為什麼要用還原價格（或分割調整後的價格）計算報酬。

### 7. ⭐ 原始價格 vs. 還原價格：什麼時候用哪一種？

| 用途 | 用哪一種 | 理由 |
|---|---|---|
| **計算報酬率、績效、回撤** | 還原價格 | 反映真實的投資報酬（含股利再投入） |
| **計算技術指標的訊號**（均線、RSI、突破） | 通常用還原價格 | 避免除息、分割造成的假訊號 |
| **計算實際下單的股數、金額** | 原始價格 | 你實際買賣的是當時的市價 |
| **和看盤軟體比對** | 看軟體的設定 | TradingView 等軟體通常可以切換是否「調整股利」 |
| **支撐壓力、整數關卡** | 原始價格 | 市場參與者看到的是原始價格 |

> 🔑 **最常見的做法**：用還原價格計算訊號與報酬；如果要模擬實際下單，再用「原始價格」計算股數與成本。不管選哪一種，**在規格書和回測報告中寫清楚**（8.13）。

### 8. 資料清理的流程（建議寫成函式）

```python
def clean_prices(df):
    """基本清理：移除重複日期、排序、移除價格不合理的列、用前值填補缺值。"""
    df = df[~df.index.duplicated(keep="first")].sort_index()
    price_cols = ["Open", "High", "Low", "Close"]
    bad = (df[price_cols] <= 0).any(axis=1) | (df["High"] < df["Low"])
    if bad.sum() > 0:
        print(f"移除 {bad.sum()} 筆價格不合理的資料：{list(df.index[bad].date)}")
    df = df[~bad].copy()          # .copy() 避免舊版 pandas 的 SettingWithCopyWarning
    n_missing = df[price_cols].isna().sum().sum()
    if n_missing > 0:
        print(f"用前一天的值填補 {n_missing} 個缺值")
    df[price_cols] = df[price_cols].ffill()
    return df

raw = pd.read_csv("sample_prices.csv", parse_dates=["Date"], index_col="Date")
df = clean_prices(raw)
print(len(raw), len(df))
```

> 🥬 **重點不是程式多複雜，而是：每一步都有理由、都印出紀錄、都不偷看未來。** 被刪掉或填補的資料要記錄下來，寫進回測報告的「資料」段落。

## 📌 重點整理

1. 髒資料：**缺值、重複、順序錯亂、異常值、除權息與分割**。
2. 重複用 `duplicated()`、順序用 `sort_index()`；有疑問的資料要回頭查、並記錄。
3. 缺值：`dropna` 或 `ffill`；**不能用 bfill 或內插**（用到未來資料）。
4. 不同市場合併時交易日不同：通常 ffill；注意**時差**。
5. **除權息**：原始價格在除息日看起來下跌，但投資人沒有虧錢；不調整會**低估報酬、產生假訊號**。
6. **分割**：價格突然變成幾分之一；不調整會出現假的暴跌。
7. **報酬與訊號用還原價格，實際下單用原始價格**，並寫進規格書。

## ❌ 常見誤解

| 誤解 | 事實 |
|---|---|
| 「缺值用後面的值補比較準」 | 用後面的值（bfill）是偷看未來，回測中不能用。 |
| 「除息那天股價下跌就是虧錢」 | 股價減少的部分以現金股利發給你，總報酬不變。 |
| 「還原價格是假的，不能用」 | 還原價格是為了正確計算報酬而調整的；計算報酬與訊號時反而比較正確。 |
| 「資料清理就是把怪怪的資料刪掉」 | 要先查原因（除權息、分割、真的錯誤），再決定調整、填補或刪除，並記錄下來。 |

## ✅ 自我測驗

**Q1. 什麼是除權息調整？為什麼不調整會讓回測出錯？**

<details><summary>看答案</summary>

除息時，股價會扣掉發放的股利，但投資人拿到等額現金，總報酬不變。除權息調整（還原價格）是把除息日之前的價格依比例往下調整，讓價格變化只反映真實漲跌。不調整的話，回測會把每次除息當成下跌，低估長期報酬；也可能讓除息造成的價格跳空觸發停損或進場訊號，產生假交易。

</details>

**Q2. 為什麼回測中填補缺值不能用 bfill？**

<details><summary>看答案</summary>

bfill 用「後一天」的值填補缺值，等於讓過去的某一天提前知道未來的價格，這是前視偏差。回測中只能用當時已知的資訊，因此缺值通常用前一天的值（ffill）填補，或直接刪除。

</details>

**Q3. 練習 3 參考答案**

<details><summary>看答案</summary>

除息日（第 3 天）的調整比例 = 1 − 1.5 ÷ 51 ≈ 0.970588。除息日之前的價格乘上這個比例：第 1 天 50 × 0.970588 ≈ 48.53、第 2 天 51 × 0.970588 = 49.50；第 3、4 天不變（49.5、50）。還原報酬：第 2 天 +2.00%、第 3 天 **0.00%**（原始報酬是 −2.94%）、第 4 天 +1.01%。

</details>
