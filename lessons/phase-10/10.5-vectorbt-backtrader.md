## 🧠 正文

### 1. 三個框架的定位

| 框架 | 類型 | 擅長 | 不擅長 | 比喻 |
|---|---|---|---|---|
| **Backtesting.py**（10.4） | 事件驅動 | 簡單易學、報表與圖表漂亮 | 多商品組合 | 入門模擬器 |
| **vectorbt** | 向量化 | **速度極快**、大量參數掃描 | 複雜的下單邏輯 | 同時模擬 100 種天氣 |
| **backtrader** | 事件驅動 | 多商品、複雜委託、接近實盤 | 速度較慢、學習曲線陡 | 完整的駕駛艙 |

> 💡 這些都是社群維護的開源專案，功能、API 和維護狀態會隨時間改變。安裝前先看官方文件與最近的更新紀錄。本單元程式在 vectorbt 1.1、backtrader 1.9 版測試過。

### 2. ⭐ vectorbt：向量化框架

```
!pip install vectorbt
```

**預設寫法：**

```python
import pandas as pd
import vectorbt as vbt

df = pd.read_csv("sample_long.csv", parse_dates=["Date"], index_col="Date")
close = df["Close"]

state = close.rolling(20).mean() > close.rolling(60).mean()      # 狀態：想不想持有
entries = state & ~state.shift(1, fill_value=False)               # 狀態從 False 變 True 的那天
exits = ~state & state.shift(1, fill_value=False)                 # 狀態從 True 變 False 的那天

pf = vbt.Portfolio.from_signals(close, entries, exits, init_cash=1_000_000, freq="1D")
print(f"總報酬：{pf.total_return():.2%}")
print(pf.trades.records_readable[["Entry Timestamp", "Avg Entry Price"]].head(2))
```

輸出：

```
總報酬：123.61%
  Entry Timestamp  Avg Entry Price
0      2010-03-26            52.08
1      2011-03-09            71.62
```

> 🚨 **總報酬 123.61%，而不是 10.2 嚴謹版的 132.44%！** 看交易紀錄：第一筆在 **3/26 以 52.08 元**進場——3/26 正是訊號出現的那天，52.08 是 3/26 的**收盤價**。
>
> vectorbt 的預設是：**訊號出現的那根 K 棒，以收盤價成交**。這和 10.2 的「簡化版」一樣（簡化版的結果正是 2.236 倍 = 123.6%）。

**改成「隔天開盤成交」：** 把訊號往後移一天，並指定成交價為開盤價。

```python
pf2 = vbt.Portfolio.from_signals(
    close,
    entries.shift(1, fill_value=False),     # 訊號隔天才執行
    exits.shift(1, fill_value=False),
    price=df["Open"],                        # 用開盤價成交
    init_cash=1_000_000,
    freq="1D",
)
print(f"總報酬：{pf2.total_return():.2%}")
print(f"最大回撤：{pf2.max_drawdown():.2%}")
print(f"交易筆數：{pf2.trades.count()}")
```

輸出：

```
總報酬：132.44%
最大回撤：-31.92%
交易筆數：34
```

和 10.2 嚴謹版**完全一致**（132.44%、−31.92%、34 筆含 1 筆未平倉）✅。

> 🔑 **每個框架的預設成交時點都可能不同**：Backtesting.py 預設下一根開盤、vectorbt 預設當根收盤。不知道預設值就直接用，等於不知道考卷怎麼計分。**這就是要用自己的版本交叉驗證的原因。**

### 3. ⭐ vectorbt 的強項：一次測試大量參數

vectorbt 可以把很多組參數的訊號**並排成很多欄**，一次全部回測：

```python
signals_in, signals_out = {}, {}
for fast in range(5, 61, 5):
    for slow in range(20, 201, 20):
        if fast >= slow:
            continue
        st = close.rolling(fast).mean() > close.rolling(slow).mean()
        signals_in[(fast, slow)] = (st & ~st.shift(1, fill_value=False)).shift(1, fill_value=False)
        signals_out[(fast, slow)] = (~st & st.shift(1, fill_value=False)).shift(1, fill_value=False)

E = pd.concat(signals_in, axis=1)
X = pd.concat(signals_out, axis=1)
E.columns.names = X.columns.names = ["fast", "slow"]

pf_all = vbt.Portfolio.from_signals(close, E, X, price=df["Open"], init_cash=1_000_000, freq="1D")
sharpe = pf_all.sharpe_ratio(year_freq="252 days")
print(f"共測試 {len(sharpe)} 組參數")
print(sharpe.sort_values(ascending=False).head(3).round(3))
```

輸出：

```
共測試 105 組參數
fast  slow
55    200     0.709
60    200     0.696
40    60      0.585
```

> 💡 105 組參數一次跑完，速度比 Backtesting.py 的 `optimize()` 快很多。最佳參數同樣是 **MA55 / MA200**，和 10.4 一致。（夏普的數值和 10.4 不同，因為公式不同——下一個重點。）
>
> ⚠️ 速度快是好事，但也讓**過度擬合變得更容易**：一次測一萬組參數只要幾秒鐘。10.12 會告訴你為什麼這很危險。

### 4. ⚠️ 指標公式的細節：年化用 365 還是 252？

```python
print(f"預設：{pf2.sharpe_ratio():.3f}")
print(f"指定 252 天：{pf2.sharpe_ratio(year_freq='252 days'):.3f}")
```

輸出：

```
預設：0.608
指定 252 天：0.505
```

`freq="1D"` 時，vectorbt 預設一年有 **365 天**；但我們的資料只有交易日（一年約 252 天）。指定 `year_freq="252 days"` 後，夏普比率 0.505 和工具箱 `perf_stats()` 的結果完全一致。

> 🔑 0.608 ÷ 0.505 ≈ √(365 ÷ 252)。**同一個策略、同一個公式，只因為一年算幾天，夏普就差了 20%。** 比較不同來源的績效指標時，一定要確認計算方式（10.8）。

### 5. backtrader：事件驅動框架

```
!pip install backtrader
```

```python
import backtrader as bt

class MaState(bt.Strategy):
    params = dict(n1=20, n2=60)

    def __init__(self):
        self.ma1 = bt.ind.SMA(self.data.close, period=self.p.n1)
        self.ma2 = bt.ind.SMA(self.data.close, period=self.p.n2)
        self.closed_trades = 0

    def next(self):
        if self.ma1[0] > self.ma2[0]:
            if not self.position:
                self.order_target_percent(target=0.99)   # 用 99% 的資金，留一點緩衝
        elif self.position:
            self.close()

    def notify_trade(self, trade):
        if trade.isclosed:
            self.closed_trades += 1


cerebro = bt.Cerebro()
cerebro.adddata(bt.feeds.PandasData(dataname=df))
cerebro.addstrategy(MaState)
cerebro.broker.setcash(1_000_000)
cerebro.addanalyzer(bt.analyzers.DrawDown, _name="dd")
result = cerebro.run()[0]

print(f"最終資產：{cerebro.broker.getvalue():,.0f}")
print(f"最大回撤：{result.analyzers.dd.get_analysis().max.drawdown:.2f}%")
print(f"已平倉交易：{result.closed_trades}")
```

輸出：

```
最終資產：2,309,907
最大回撤：31.61%
已平倉交易：33
```

| 對照 | 說明 |
|---|---|
| backtrader 的 `self.ma1[0]` | `[0]` 是目前這根 K 棒（Backtesting.py 用 `[-1]`）——每個框架的慣例不同！ |
| 委託預設下一根開盤成交 | 和我們的嚴謹版一致 |
| 為什麼用 99% 而不是 100%？ | 委託在隔天開盤才成交，如果開盤跳空上漲，100% 的資金會不夠而被拒絕 |
| 最終資產比 10.2 略低 | 只投入 99% 的資金，所以報酬約為全額的 99% |

> 💡 backtrader 的優勢在更複雜的場景：多檔商品、停損停利單、分批進出、券商介面。本課程不會深入，知道它的存在和基本結構就好。

### 6. ⭐ 四方比對總表

| 版本 | 成交時點 | 總報酬 | 最大回撤 | 備註 |
|---|---|---:|---:|---|
| 10.2 自己寫（簡化版） | 訊號當天收盤 | 123.61% | — | |
| vectorbt（預設） | 訊號當天收盤 | 123.61% | — | 和簡化版一致 |
| 10.2 自己寫（嚴謹版） | 隔天開盤 | 132.44% | −31.92% | |
| vectorbt（調整後） | 隔天開盤 | 132.44% | −31.92% | 完全一致 |
| Backtesting.py（10.4） | 隔天開盤 | 133.47% | −31.92% | 暖機期、整數股 |
| backtrader | 隔天開盤 | 130.99% | −31.61% | 只投入 99% 資金 |

> 🔑 **四個獨立的實作，在相同假設下結果幾乎一致**——你現在可以非常有信心：這個策略在這份資料上的表現就是這樣。而每一個差異，你都說得出原因。**這就是「可信的回測」的第一步。**

### 7. 如何選擇框架？

| 你的需求 | 建議 |
|---|---|
| 學習、單一商品、想要漂亮的報表 | **Backtesting.py** |
| 大量參數掃描、研究很多想法 | **vectorbt**（小心過度擬合） |
| 多商品組合、複雜委託、未來想接實盤 | **backtrader** 或其他事件驅動框架 |
| 想完全掌握每個細節 | **自己寫**（10.2、10.3），並用框架驗證 |

> 💡 **不要追求「最好的框架」**。選一個主要使用，再用另一個（或自己寫的版本）交叉驗證，比熟悉五個框架更重要。

---

## 📌 重點整理

1. 學第二個框架 = **多一個交叉驗證的來源**。
2. **vectorbt**：向量化、超快、擅長大量參數掃描；**預設訊號當根收盤成交**。
3. 改成隔天開盤：**訊號 shift(1) + price=Open**，結果和 10.2 嚴謹版完全一致。
4. 指標細節：vectorbt 預設一年 **365 天**，要指定 `year_freq="252 days"`。
5. **backtrader**：事件驅動、適合複雜場景；`[0]` 是目前 K 棒；用 99% 資金避免跳空時委託被拒。
6. **四方比對**：相同假設下結果一致，差異都說得出原因 → 可信回測的第一步。
7. 選一個主要框架 + 一個驗證來源，比追求最好的框架重要。

## ❌ 常見誤解

| 誤解 | 事實 |
|---|---|
| 「所有框架的預設成交方式都一樣」 | Backtesting.py 預設下一根開盤，vectorbt 預設當根收盤；一定要確認。 |
| 「框架算的夏普比率可以直接互相比較」 | 年化天數、平均方式等細節不同，同一策略可能差 20% 以上。 |
| 「框架越快越好」 | 快速讓大量參數測試變容易，也讓過度擬合變容易。 |
| 「要把每個框架都學精」 | 一個主要框架 + 一個驗證來源就足夠。 |

## ✅ 自我測驗

**Q1. vectorbt 的預設成交方式是什麼？如何改成「隔天開盤成交」？**

<details><summary>看答案</summary>

預設在訊號出現的那根 K 棒以收盤價成交（等同 10.2 的簡化版）。要改成隔天開盤成交，把進出場訊號都 shift(1)，並在 `from_signals` 中指定 `price=df["Open"]`。

</details>

**Q2. 同一個策略，vectorbt 預設的夏普比率 0.608，工具箱算出 0.505，為什麼？**

<details><summary>看答案</summary>

因為年化方式不同：`freq="1D"` 時 vectorbt 預設一年 365 天，而工具箱用一年 252 個交易日。兩者相差約 √(365/252) 倍。指定 `year_freq="252 days"` 後兩者一致。這說明比較績效指標時必須確認計算方式。

</details>

**Q3. 為什麼要用多個框架（或自己寫的版本）回測同一個策略？**

<details><summary>看答案</summary>

每個框架都有自己的預設假設（成交時點、資金使用、暖機期、指標公式），而且都可能有 bug 或被誤用。多個獨立實作在相同假設下結果一致，才能確信回測正確；結果不同時，追查差異能幫助你理解並統一假設。

</details>
