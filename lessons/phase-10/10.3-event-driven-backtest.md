## 🎯 學完你會知道

- **事件驅動回測**是什麼：一天一天、一個事件一個事件地重演歷史
- 每一天的**三個時間點**：開盤、盤中、收盤，各自該做什麼
- 用迴圈寫出一個**有現金、有股數**的簡單回測引擎
- 驗證：沒有停損時，結果和 10.2 的向量化回測**一致**
- 加入**ATR 停損**這種向量化很難處理的規則
- 停損後「要不要重新進場？」——寫程式逼你面對的規格問題
- 向量化 vs. 事件驅動：什麼時候用哪一種

## 📖 開場故事：重演一場球賽

球隊教練想研究上一場比賽輸在哪裡。他有兩種方法：

**方法一：看數據總表**
「控球率 55%、射門 12 次、命中 3 次。」很快就能看完，適合比較很多場比賽的整體表現。

**方法二：重播比賽錄影，一分鐘一分鐘看**
「第 23 分鐘，對方反擊時我們的後衛站錯位置；第 24 分鐘，守門員判斷失誤……」很花時間，但能看到**每一個決策當下的狀況**。

> ⚽ **向量化回測像看數據總表**：一次算完整欄，又快又簡潔。**事件驅動回測像重播錄影**：一天一天（甚至一筆一筆）重演，每個時間點只看當時知道的資訊、做當時能做的決定。遇到停損、移動停損、加碼這類「要看當時狀況才能決定」的規則，就需要重播錄影。

## 🧠 正文

### 1. ⭐ 一天的三個時間點

事件驅動回測的核心，是嚴格按照**真實的時間順序**處理每一件事：

| 時間點 | 你知道什麼 | 能做什麼 |
|---|---|---|
| **① 開盤** | 昨天以前的所有資料 + 今天的開盤價 | 執行**昨天收盤後**決定的委託（買進 / 賣出） |
| **② 盤中** | 今天的最高價、最低價（事後才知道整天的範圍） | 檢查**停損單**、限價單是否被觸發 |
| **③ 收盤** | 今天的收盤價 | 記錄資產價值；根據收盤資料**產生明天的委託** |

> 🔑 **順序就是一切**：今天收盤才產生的訊號，只能在明天開盤執行。在迴圈中，只要按照 ①→②→③ 的順序寫，就自然不會偷看未來。

### 2. ⭐ 寫一個簡單的事件驅動引擎

```python
import pandas as pd
import numpy as np
from bt_toolkit import load_prices, sma, atr, perf_stats

df = load_prices("sample_long.csv")
df["MA20"] = sma(df["Close"], 20)
df["MA60"] = sma(df["Close"], 60)
df["ATR20"] = atr(df, 20)


def run_event(df, stop_atr=None, cash=1_000_000):
    """事件驅動回測：MA20 > MA60 時持有；可選擇加入 ATR 停損。"""
    shares = 0
    pending = None          # 昨天收盤後決定的委託："buy"、"sell" 或 None
    stop = None
    equity, trades = [], []

    for i in range(len(df)):
        row = df.iloc[i]
        date = df.index[i]

        # ① 開盤：執行昨天收盤後決定的委託
        if pending == "buy" and shares == 0:
            shares = int(cash / row["Open"])                  # 整數股數
            cash -= shares * row["Open"]
            entry_date, entry_price = date, row["Open"]
            if stop_atr:
                stop = row["Open"] - stop_atr * df["ATR20"].iloc[i - 1]   # 用昨天的 ATR
        elif pending == "sell" and shares > 0:
            cash += shares * row["Open"]
            trades.append((entry_date, date, entry_price, row["Open"], "訊號出場"))
            shares, stop = 0, None
        pending = None

        # ② 盤中：檢查停損
        if shares > 0 and stop is not None and row["Low"] <= stop:
            price = min(row["Open"], stop)                     # 開盤就跳空跌破 → 用開盤價
            cash += shares * price
            trades.append((entry_date, date, entry_price, price, "停損"))
            shares, stop = 0, None

        # ③ 收盤：記錄資產，產生明天的委託
        equity.append(cash + shares * row["Close"])
        want = row["MA20"] > row["MA60"]
        if want and shares == 0:
            pending = "buy"
        elif not want and shares > 0:
            pending = "sell"

    trades = pd.DataFrame(trades, columns=["進場日", "出場日", "進場價", "出場價", "原因"])
    return pd.Series(equity, index=df.index), trades
```

> 💡 和 10.2 最大的不同：這裡有**現金**和**股數**兩個「狀態」，每天根據狀態做決定。這正是 9.4 學過的迴圈與累加器。

### 3. ⭐ 驗證：和向量化回測一致嗎？

```python
equity, trades = run_event(df)
print(f"最終資產：{equity.iloc[-1]:,.0f}（倍數 {equity.iloc[-1] / 1_000_000:.4f}）")
print(f"交易筆數：{len(trades)}")
print(trades.head(3))
```

輸出：

```
最終資產：2,324,328（倍數 2.3243）
交易筆數：33
         進場日        出場日    進場價    出場價    原因
0 2010-03-29 2011-01-19  52.07  70.88  訊號出場
1 2011-03-10 2011-03-29  71.44  70.94  訊號出場
2 2011-04-18 2011-06-27  73.90  72.27  訊號出場
```

10.2 向量化回測的最終倍數是 **2.324**，事件驅動是 **2.3243**——幾乎完全一樣 ✅。微小差距來自**整數股數**：事件驅動每次買進只能買整數股，剩下一點零錢沒有投入。

> 🔑 **用兩種方法算同一個策略，結果應該一致**。這是抓 bug 最有效的方法之一：兩個獨立寫出來的程式犯同一個錯的機率很低。（交易筆數 33 vs. 10.2 的進場 34 次：最後一筆在資料結束時還沒賣出，事件驅動版沒有把它記錄成一筆完成的交易。）

### 4. ⭐ 加入 ATR 停損

規則：進場後，停損設在「進場價 − 2 × ATR(20)」（回想 6.5）；盤中最低價碰到就出場。

```python
equity_stop, trades_stop = run_event(df, stop_atr=2)
print(f"最終倍數：{equity_stop.iloc[-1] / 1_000_000:.4f}")
print(f"交易筆數：{len(trades_stop)}，其中停損 {(trades_stop['原因'] == '停損').sum()} 筆")

for name, eq in [("無停損", equity), ("2ATR 停損", equity_stop)]:
    s = perf_stats(eq.pct_change())
    print(f"{name}：年化 {s['年化報酬']:.2%}，最大回撤 {s['最大回撤']:.2%}，夏普 {s['夏普比率']:.2f}")
```

輸出：

```
最終倍數：2.3922
交易筆數：57，其中停損 24 筆
無停損：年化 6.22%，最大回撤 -31.91%，夏普 0.51
2ATR 停損：年化 6.44%，最大回撤 -32.87%，夏普 0.53
```

**仔細看幾個細節：**

| 細節 | 程式怎麼處理 | 為什麼 |
|---|---|---|
| 停損價用哪一天的 ATR？ | **昨天**的 ATR（`iloc[i - 1]`） | 開盤時還不知道今天的 ATR |
| 開盤就跳空跌破停損？ | 用**開盤價**出場（`min(Open, stop)`） | 跳空時你根本賣不到停損價（1.10、8.13） |
| 同一天盤中先漲後跌？ | 只看最低價有沒有碰到 | 日線資料不知道盤中順序，保守假設碰到就出場 |

### 5. ⭐ 規格問題：停損後要不要重新進場？

加了停損後，交易筆數從 33 筆增加到 **57 筆**。為什麼？

看程式：停損出場後，如果收盤時 MA20 仍然 > MA60，`want` 還是 True，**隔天開盤就又買回來了**。

```python
print(trades_stop[trades_stop["原因"] == "停損"].head(3))
```

輸出：

```
         進場日        出場日    進場價        出場價  原因
0 2010-03-29 2010-04-02  52.07  50.670801  停損
2 2011-03-10 2011-03-17  71.44  69.219772  停損
3 2011-03-18 2011-03-22  70.02  67.572216  停損
```

2011-03-17 停損、03-18 立刻又買回去、03-22 又停損。這是你要的嗎？

| 選項 | 規則 | 效果 |
|---|---|---|
| A. 立刻重新進場 | 只要訊號還在就買回 | 可能在震盪中反覆停損 |
| B. 等新的交叉 | 停損後要等 MA20 先跌破、再重新站上 MA60 | 交易較少，但可能錯過趨勢延續 |
| C. 冷卻期 | 停損後 N 天內不進場 | 折衷 |

> 🔑 **這就是 8.13 說的「寫程式會逼你面對規格書的模糊之處」**。規格書只寫了「2ATR 停損」，沒寫停損後怎麼辦，電腦就照最字面的方式做了。**沒有標準答案，但一定要寫清楚**，並分別回測比較（練習 2）。

### 6. 向量化 vs. 事件驅動

| | 向量化（10.2） | 事件驅動（本單元） |
|---|---|---|
| 比喻 | 看數據總表 | 重播比賽錄影 |
| 速度 | 非常快 | 慢（一天一天跑） |
| 程式 | 短 | 較長 |
| 停損、移動停損、加碼 | 很難 | **容易** |
| 現金、整數股、多檔股票的資金分配 | 很難 | **容易** |
| 前視偏差風險 | 容易忘了 shift | 照時間順序寫，比較不容易犯錯 |
| 適合 | 快速篩選大量想法、參數掃描 | 精細模擬實際交易 |

> 💡 **實務上常常兩個一起用**：先用向量化快速篩選，留下有希望的想法，再用事件驅動（或 10.4 的框架）做精細的回測。兩者結果應該大致一致——不一致就是有 bug 或假設不同。

---

## 📌 重點整理

1. 事件驅動 = **重播錄影**：一天一天、按照時間順序重演。
2. 每天三個時間點：**開盤執行昨天的委託 → 盤中檢查停損 → 收盤記錄並產生明天的委託**。
3. 照時間順序寫，**自然不會偷看未來**。
4. **兩種方法算同一個策略應該一致**——這是抓 bug 的利器。
5. 事件驅動能處理**停損、跳空、整數股、現金**等細節。
6. 寫程式會逼你回答規格問題，例如**停損後要不要重新進場**。
7. 實務上：**向量化快速篩選 + 事件驅動精細驗證**。

## ❌ 常見誤解

| 誤解 | 事實 |
|---|---|
| 「事件驅動一定比向量化準確」 | 兩者假設相同時結果應該一致；事件驅動的優勢是能處理更複雜的規則與細節。 |
| 「停損價一定能成交」 | 開盤跳空跌破停損時，只能用開盤價（或更差的價格）出場。 |
| 「加了停損就一定比較好」 | 停損可能讓你在震盪中反覆出場，要回測比較並思考重新進場的規則。 |
| 「日線回測可以知道盤中先碰到高點還是低點」 | 日線不知道盤中順序，只能做保守假設。 |

## 🛠️ 練習（約 75 分鐘）

**練習 1：驗證一致性**
執行本單元的程式，確認無停損版本和 10.2 的結果一致。再把 `int(cash / row["Open"])` 改成不取整數（`cash / row["Open"]`），結果是否和 10.2 完全一樣？

**練習 2：停損後的重新進場規則**
修改 `run_event()`，實作第 5 節的選項 B（停損後要等 MA20 先跌破 MA60、再重新站上才進場）與選項 C（冷卻期 10 天）。比較三種選項的年化報酬、最大回撤、交易筆數。

**練習 3：移動停損**
把固定停損改成 8.3 的移動停損：「持倉期間最高收盤價 − 3 × ATR(20)」，每天收盤後更新停損價（只能往上移）。和固定停損比較結果。

**練習 4：RSI(2) 均值回歸**
用事件驅動的寫法實作 8.5 的範例 A：收盤 > 200 日均線且 RSI(2) < 10 → 隔天開盤買進；收盤 > 5 日均線 → 隔天開盤賣出；持有滿 10 個交易日 → 隔天開盤賣出。（這種進出條件不同、又有時間停損的規則，用事件驅動寫起來最自然。）

## ✅ 自我測驗

**Q1. 事件驅動回測中，一天的三個時間點分別要做什麼？**

<details><summary>看答案</summary>

① 開盤：執行昨天收盤後決定的委託（以開盤價成交）；② 盤中：用當天的最高、最低價檢查停損或限價單是否觸發；③ 收盤：記錄當天的資產價值，並根據收盤資料產生明天要執行的委託。

</details>

**Q2. 為什麼要用向量化和事件驅動兩種方法回測同一個策略？**

<details><summary>看答案</summary>

兩個獨立寫出的程式，在相同假設下結果應該一致。如果一致，能大幅提高對結果正確性的信心；如果不一致，代表其中一個有 bug，或兩者的假設不同（例如成交價、整數股），可以藉此找出問題。

</details>

**Q3. 計算停損價時，為什麼用「昨天」的 ATR？**

<details><summary>看答案</summary>

因為停損價在今天開盤進場時就要設定，那時候今天的最高、最低、收盤價都還不知道，今天的 ATR 也還無法計算。用今天的 ATR 就是使用了當時還不知道的資訊（前視偏差）。

</details>
