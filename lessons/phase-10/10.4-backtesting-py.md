### 3. ⭐ 第一個策略：均線狀態策略

```python
import pandas as pd
from backtesting import Backtest, Strategy

df = pd.read_csv("sample_long.csv", parse_dates=["Date"], index_col="Date")


def SMA(values, n):
    """Backtesting.py 會把價格以陣列傳進來，轉成 Series 才能用 rolling。"""
    return pd.Series(values).rolling(n).mean()


class MaState(Strategy):
    n1 = 20      # 參數寫成類別變數，之後可以最佳化
    n2 = 60

    def init(self):
        # init()：回測開始前執行一次，計算指標
        self.ma1 = self.I(SMA, self.data.Close, self.n1)
        self.ma2 = self.I(SMA, self.data.Close, self.n2)

    def next(self):
        # next()：每一根 K 棒收盤時執行一次，決定要不要下單
        if self.ma1[-1] > self.ma2[-1]:
            if not self.position:
                self.buy()
        elif self.position:
            self.position.close()


bt = Backtest(df, MaState, cash=1_000_000, commission=0.0)
stats = bt.run()
print(stats)
```

**結構對照 10.3 的事件驅動：**

| Backtesting.py | 10.3 的事件驅動 | 說明 |
|---|---|---|
| `init()` | 迴圈前算好 MA、ATR | 指標只算一次 |
| `next()` | 第 ③ 步「收盤」 | 每根 K 棒收盤時，用當時的資料決定委託 |
| `self.buy()`、`self.position.close()` | `pending = "buy"` / `"sell"` | 委託在**下一根 K 棒的開盤**成交（預設） |
| `self.ma1[-1]` | `row["MA20"]` | `[-1]` 代表「目前這根 K 棒」的值 |
| `self.I(...)` | — | 把指標登記給框架，它會自動處理「只看得到過去」 |

> ⚠️ **資料格式**：Backtesting.py 要求欄位名稱是 `Open`、`High`、`Low`、`Close`（大寫開頭），`Volume` 可選；索引是日期。

### 5. ⭐⭐ 課綱作業：和 10.2 的結果比對

| 指標 | 10.2 自己寫（嚴謹版） | Backtesting.py |
|---|---:|---:|
| 總報酬 | 132.44% | 133.47% |
| 年化報酬 | 6.22% | 6.25% |
| 最大回撤 | −31.92% | −31.92% |
| 完成的交易筆數 | 33（另有 1 筆未平倉） | 33 |
| 第 2 筆交易 | 2011-03-10 進、03-29 出 | 2011-03-10 進、03-29 出 ✅ |

**結果非常接近，但不完全相同。差異從哪裡來？**

| 差異 | 原因 |
|---|---|
| **第一筆的進場日不同**（10.2 是 3/29，框架是 3/30） | Backtesting.py 要等**所有指標都有值的下一根 K 棒**才開始呼叫 `next()`。MA60 在 3/26 才有第一個值，框架從 3/29 開始判斷，3/30 才成交 |
| **整數股** | 框架只買整數股（`Size` 欄位），而且預設只用約 99.99% 的資金 |
| **買進持有報酬不同**（219.88% vs. 207.10%） | 起算點不同：框架從開始交易的那根 K 棒算起 |
| **夏普比率不同**（0.51 vs. 0.43） | 公式不同（10.8 會說明：用算術平均或幾何平均、是否包含暖機期） |
| **最後一筆未平倉交易** | 框架預設在資料結束時不計入未平倉交易 |

> 🔑 **這就是交叉驗證的價值**：兩者的交易幾乎一筆一筆對得上，你可以很有信心兩邊都沒有大 bug；而每一個差異你都**說得出原因**。如果差了 50%，或交易日期對不上，那就一定有一邊錯了——通常是自己寫的那一邊忘了 shift，或用錯了成交價。

### 6. 設定交易成本

`commission` 是**每次成交金額的比例**（買和賣都收同樣比例）：

```python
from bt_toolkit import tw_costs

buy_cost, sell_cost = tw_costs()                 # 台股：買 0.0855%，賣 0.3855%（含 0.3% 交易稅）
avg_cost = (buy_cost + sell_cost) / 2            # Backtesting.py 買賣同費率：用平均值，讓一買一賣的總成本相同
print(f"買 {buy_cost:.4%}，賣 {sell_cost:.4%}，平均 {avg_cost:.4%}")

stats_cost = Backtest(df, MaState, cash=1_000_000, commission=avg_cost).run()
print(f"含成本：總報酬 {stats_cost['Return [%]']:.2f}%，年化 {stats_cost['CAGR [%]']:.2f}%，"
      f"最大回撤 {stats_cost['Max. Drawdown [%]']:.2f}%")
```

輸出：

```
買 0.0855%，賣 0.3855%，平均 0.2355%
含成本：總報酬 99.39%，年化 5.06%，最大回撤 -35.35%
```

和工具箱 `backtest(df, signal, *tw_costs())` 的結果（總報酬 98.76%、年化 5.04%、最大回撤 −35.36%）幾乎一致 ✅。成本讓總報酬從 133% 掉到 99%——10.6 會深入討論。

> ⚠️ 台股買賣成本不對稱（賣出才有交易稅），而 Backtesting.py 的 `commission` 是對稱的。用平均值可以讓「一買一賣」的總成本正確；如果你的策略常常只買不賣（或反過來），要注意這個近似。

### 8. ⚠️ 參數最佳化：強大但危險的按鈕

Backtesting.py 可以自動測試很多組參數，找出「最好的」：

```python
best = bt.optimize(
    n1=range(5, 61, 5),
    n2=range(20, 201, 20),
    constraint=lambda p: p.n1 < p.n2,     # 短均線要比長均線短
    maximize="Sharpe Ratio",
)
print(best._strategy)
print(f"夏普 {best['Sharpe Ratio']:.2f}，年化 {best['CAGR [%]']:.2f}%，最大回撤 {best['Max. Drawdown [%]']:.2f}%")
```

輸出：

```
MaState(n1=55,n2=200)
夏普 0.62，年化 8.94%，最大回撤 -19.99%
```

哇！MA55 / MA200 的年化報酬 8.94%，**贏過買進持有**，最大回撤只有 −20%。找到聖杯了？

> 🚨 **還不能高興。** 這組參數是從 105 組裡面「挑」出來、剛好最適合**這段歷史**的。回想 10.1 的猴子：測試越多組，越容易挑到運氣好的。
>
> 這組參數在**沒看過的資料**上還會這麼好嗎？10.12～10.15 會用樣本外測試、walk-forward、參數高原來檢驗它。**在那之前，請把最佳化結果當成「需要被懷疑的假說」，不是結論。**

## 📌 重點整理

1. 框架 = **電腦閱卷系統**：快、功能齊全，但要知道它的預設假設。
2. Backtesting.py 結構：`init()` 算指標（用 `self.I`）、`next()` 每根 K 棒收盤時決定委託。
3. 預設**下一根 K 棒開盤成交**，和我們的嚴謹版一致。
4. **交叉驗證**：和 10.2 比對，交易應該幾乎一筆一筆對得上，差異要說得出原因（暖機期、整數股、起算點、指標公式）。
5. `commission` 是對稱的比例；台股不對稱成本可用平均值近似。
6. `bt.plot()` 畫互動圖，**一定要打開看**。
7. `optimize()` 很強大也很危險：最佳參數只是**需要被懷疑的假說**。

## ❌ 常見誤解

| 誤解 | 事實 |
|---|---|
| 「框架算出來的一定是對的」 | 框架只會照你寫的規則與它的預設假設計算；要用自己的版本交叉驗證。 |
| 「兩個回測結果有一點差異，一定有一個錯了」 | 小差異常來自暖機期、整數股、起算點、指標公式；要說得出原因。差異很大才是 bug。 |
| 「optimize 找到的參數就是最好的參數」 | 那是最適合過去這段資料的參數，很可能是過度擬合。 |
| 「不同框架的夏普比率可以直接比較」 | 各框架的計算方式可能不同；比較時要用同一套公式。 |

**練習 1：課綱作業——交叉驗證**

**練習 2：交叉型 vs. 狀態型**
把 `next()` 改成只在「交叉那一天」進出場（提示：`from backtesting.lib import crossover`，`if crossover(self.ma1, self.ma2): self.buy()`、`elif crossover(self.ma2, self.ma1): self.position.close()`），和狀態型比較交易筆數與報酬。差異從哪裡來？

**練習 3：加入停損**
Backtesting.py 的 `self.buy(sl=...)` 可以設定停損價。用 `self.I` 計算 ATR，在 `next()` 中以 `sl=self.data.Close[-1] - 2 * atr` 下單，和 10.3 的事件驅動停損版本比較。（提示：兩者的停損價計算基準可能不同——一個用進場價、一個用訊號日收盤價，寫下差異。）

**練習 4：最佳化的誘惑**
執行第 8 節的最佳化，記下最佳參數。先不要相信它——把它寫進「待驗證假說」清單，10.13 會用樣本外資料檢驗。

## ✅ 自我測驗

**Q1. Backtesting.py 中 `init()` 和 `next()` 分別做什麼？**

<details><summary>看答案</summary>

`init()` 在回測開始前執行一次，用來計算指標（透過 `self.I` 登記，框架會確保每根 K 棒只看得到過去的值）；`next()` 在每一根 K 棒收盤時執行，根據當時的資料決定下單或平倉，委託預設在下一根 K 棒開盤成交。

</details>

**Q2. 你的回測和框架的結果有些微差異，該怎麼處理？**

<details><summary>看答案</summary>

逐一比對交易紀錄（進出場日期、價格），找出差異的原因，例如：框架的暖機期（等所有指標都有值才開始）、整數股與資金使用比例、買進持有的起算點、指標或夏普比率的公式、未平倉交易的處理。能解釋的小差異是可以接受的；差異很大或交易對不上，代表有 bug 或假設不一致，必須找出來。

</details>

**Q3. 為什麼對 `optimize()` 的結果要特別小心？**

<details><summary>看答案</summary>

因為最佳化是在同一段歷史資料上測試大量參數組合，再挑出表現最好的一組。測試越多組，越容易挑到只是剛好適合這段資料（甚至純屬運氣）的參數，在未來的表現往往會變差。必須用樣本外測試、walk-forward、參數穩健性等方法驗證。

</details>
